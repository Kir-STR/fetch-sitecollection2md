# fetch-sitecollection2md — дизайн v1

Дата: 2026-09-25. Предыстория и решения обсуждения — `docs/idea.md`.

## Цель

Собирать коллекции «готовых решений, которые люди публикуют» (made-with витрины, шаблоны автоматизаций,
галереи) в датированные снимки для агентов. Агенты по снимкам ищут потенциальные wedge для продуктов.
Анализ, формулировка job, связи между записями, проверка спроса — вне инструмента.

## Границы

- Инструмент делает только fetch. Без LLM.
- Ядро простое и общее; адаптер — один JS-файл на коллекцию.
- Браузера в ядре нет. Если источник без JS не отдаёт данные — `playwright` внутри конкретного адаптера
  (в v1 не требуется). Разведка SPA-источников при написании адаптера — `chrome-devtools-mcp` как помощник
  агента, не зависимость.
- Сравнение снимков, md → html для человека, enrich — не в v1.

## Стек

Node (ESM, JS без сборки), встроенный `fetch`, тесты — `node:test`. Единственная зависимость — `cheerio`
(HTML-адаптеры).

## Интерфейс

```
node fetch.js <collection> [--out <root>]
```

- `<collection>` — имя файла адаптера `adapters/<collection>.js`.
- `--out` задаёт корень; `<collection>/` добавляется всегда. По умолчанию корень —
  `!all/data/my/tools/fetch-sitecollection2md/`, вычисляется от расположения репозитория
  (`<repo>/../../../../data/my/tools/fetch-sitecollection2md`).
- Результат — `<root>/<collection>/YYYY-MM-DD.md` и `YYYY-MM-DD.jsonl` (дата локальная).
- Код выхода 0 при успехе, ненулевой при любой ошибке. Предупреждения и итог (записей, пропущено, дублей) — в stderr.

## Контракт адаптера

```js
export default {
  url: 'https://…',            // URL коллекции, идёт в шапку md
  delayMs: 1000,               // необязательно, пауза между запросами
  async fetch(ctx) { return records }
}
```

`ctx.get(url, init?)` возвращает `Response`; адаптер сам вызывает `.text()` / `.json()`. Пагинация, разбор и
приведение к записи — в адаптере.

`ctx.note(text)` — строка о границах данных (срез, лимит, сортировка) для шапки md; можно вызывать многократно.

## Запись

| Поле | Тип | Смысл |
|---|---|---|
| `title` | string, обязательно | название |
| `url` | string, обязательно | канонический URL, ключ записи |
| `source` | string | имя коллекции; проставляет ядро |
| `description` | string | как на сайте, без переписывания |
| `tags` | string[] | категории/разделы источника |
| `signal` | string \| null | главный сигнал популярности: `"3819 views"`, `"20 stars"`; известный ноль — `"0 views"`; нет данных — `null` |
| `extra` | object | специфика источника (вторичные сигналы, автор, дата, интеграции) |

## Ядро

1. **HTTP (`ctx.get`).** User-Agent инструмента, пауза `delayMs` (по умолчанию 1000) между запросами,
   тайм-аут попытки 30 с (`AbortSignal.timeout`). Повторы (3 попытки) — на сетевую ошибку, тайм-аут, 429 и 5xx; `Retry-After` в секундах и в HTTP-дате, не более 60 с.
   Остальные не-2xx — сразу исключение с URL и статусом. Исчерпание попыток — исключение с URL и последней причиной.
   Задержки параметризуются, чтобы тесты шли быстро.
2. **Валидация.** Запись без непустых `title` или `url` пропускается с предупреждением. 0 валидных — ошибка.
3. **Дедупликация** по `url`, сохраняется первая запись; число дублей — в итог.
4. **Рендер md.** Шапка: коллекция, URL коллекции, дата, число записей, строки `ctx.note` (в JSONL не попадают). Далее блок на запись:
   ```
   ## <title>
   - url: …
   - description: …
   - tags: a, b
   - signal: …
   - extra: {"…": …}
   ```
   Пустые/`null` поля не выводятся. JSONL — одна запись на строку, те же записи и порядок.
5. **Запись файлов.** Оба файла полностью пишутся во временные рядом с итоговыми, затем переименовываются:
   сначала `.jsonl`, потом `.md`. Ошибка адаптера, валидации или подготовки временных файлов — итоговые файлы
   не трогаются, временные удаляются. Повторный запуск в тот же день заменяет снимок дня.
   Ошибка любого переименования — ненулевой код выхода.
   Остаточный риск: смерть процесса или ошибка второго переименования оставляют при первом запуске дня только
   `.jsonl`, при повторном — новый `.jsonl` и старый `.md`; лечится следующим успешным запуском.

## Адаптеры v1

Структура источников проверена на живых данных 2026-09-25.

**n8n** — JSON API `https://api.n8n.io/templates/search?page=N&rows=250&sort=views:desc`, страницы с 1,
`rows` ≤ 250 (500 → ошибка API), сортировка `views:desc` (`createdAt:desc` тоже работает).
- Берётся top-N по просмотрам, N = 1000 (константа адаптера): 4 запроса. Ожидается ровно `min(N, totalWorkflows)`
  записей; пустая или неполная страница до этого числа — ошибка.
- `ctx.note`: `top <N> of <totalWorkflows> templates by views (desc)` — чтобы агент видел, что это срез.
- Ограничение: `views` накопительные, в топе преобладают старые шаблоны. Срез «новые» (`createdAt:desc`) — бэклог.
- `title` = `name`; `url` = `https://n8n.io/workflows/<id>` (301 на slug-адрес);
  `description` = текст с пробельными символами, схлопнутыми в один пробел, не более 500 символов, при обрезке —
  `…` в пределах лимита (одинаково в md и JSONL; осознанно сокращённый снимок; первый абзац не годится — часто
  это «Task:», «Description», «How it works:»); `signal` = `<totalViews> views`;
  `extra` = `price`, `createdAt`, `author` (`user.username`), `nodes` (`nodes[].displayName`, уникальные).
- robots.txt `api.n8n.io` — `Disallow: /`; принято: снимки редкие, с паузой.

**awesomejev** — `https://awesomejev.com/`, один статический HTML, 1 094 записи.
- Разделы — `section.cat`, название раздела — первый `span` в `.win-bar` («04 · Agent tooling» → «Agent tooling»).
  Запись — `tr[data-name]` внутри раздела.
- `title` = текст `td.c-name > a`; `url` = его `href`; `description` = `td.c-desc`; `tags` = [раздел, язык `td.c-lang`];
  `signal` = `<N> stars` из `★ N` в `td.c-stars`; `—` (нет GitHub-репо) → `null`;
  `extra` = `owner` (`span.owner`), `repo`/`site` (ссылки `[repo]`/`[site]` в `td.c-links`), `added` (`data-added`).

**replit** — `https://replit.com/gallery`, данные в `__NEXT_DATA__` (`script#__NEXT_DATA__`).
- Запись — любой объект с `_type: "galleryPage"` в JSON (рекурсивный обход). На `/gallery` 82 уникальные записи;
  страницы категорий новых не дают. В `https://replit.com/marketing-sitemap/sitemap.xml` 95 уникальных slug
  (`/gallery/<group>/<category>/<slug>`): для slug, не найденных на `/gallery`, запрашивается их страница
  (сейчас 13), из неё берётся объект с этим slug.
- `title` = `title`; `url` = `https://replit.com/gallery/<categoryTags[0].parentUseCaseTags[0].slug>/<categoryTags[0].slug>/<slug>`;
  `description` = `deck`; `tags` = `categoryTags[].title`; `signal` = `<viewCount> views`, нет `viewCount` → `null`;
  `extra` = `remixCount`, `creator` (`creatorName`), `types` (`typeTags[].title`).

**madewithlaya** — `https://www.madewithlaya.com/`, Next.js SSR, 115 записей: `/` (40), `/page/2` (40), `/page/3` (35).
- Обход: `/`, затем `/page/N+1`, пока на странице есть ссылка `href="/page/<N+1>"`.
- Запись — `article`. `title` = текст `h3 a`; `url` = `https://www.madewithlaya.com` + его `href` (`/builds/<slug>`);
  `description` = `p.mt-3`; `tags` = [категория — последний `span.truncate` в плашке `◫ GitHub · <категория>`];
  `extra` = `author` (`p.truncate.font-medium`), `sourceUrl` (`a[aria-label="Open the source"]`), `kind` (`span.shrink-0`).
- `signal` = `null`: счётчик upvotes в SSR — 0 у всех 115 записей, сигналом не является.
  `ctx.note`: `upvotes not available (SSR renders 0)`.

## Тесты

- **Ядро** (синтетические данные): `ctx.note` в шапке md и отсутствие в JSONL, тайм-аут попытки с повтором, валидация и пропуск, 0 записей → ошибка, дедупликация, рендер md и JSONL,
  вычисление пути и `--out`, запись: успех, замена снимка дня, ошибка подготовки временных файлов сохраняет
  существующий снимок. HTTP — на локальном `http.createServer`: 200, сетевая ошибка, 5xx с последующим успехом,
  429 с `Retry-After` в секундах и HTTP-дате, исчерпание попыток, немедленный отказ на 404.
- **Адаптеры** — реальные ответы источников в `test/fixtures/<collection>/` (не подделываются). `ctx.get` отдаёт
  фикстуры и журналирует URL; тест проверяет запрошенные URL, число записей и поля нескольких конкретных записей.
  n8n — несколько страниц и остановка на N (фикстуры сняты с малым `rows`), madewithlaya — несколько страниц; replit — с естественными дублями.
- **Живой прогон** `node fetch.js <collection>` по всем четырём до объявления готовности; снимки — в корень данных.
